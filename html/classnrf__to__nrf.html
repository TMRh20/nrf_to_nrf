◆ begin()

bool nrf_to_nrf::begin ( )

Begin operation of the radio

Call this in setup(), before calling any other methods. It starts the high and low frequency clocks and configures the radio with these defaults: channel 76 (2476 MHz), 1 Mbps, 16-bit CRC, maximum PA level, 5-byte addresses, 32-byte static payloads, auto-ack on all pipes, and 5 retries with a delay of 5. It also enables the RX interrupt with enableRxInterrupt().

if (!radio.begin()) {
Serial.println(F("radio hardware not responding!"));
while (1) {} // hold program in infinite loop to prevent subsequent errors
}
Returns
  • true if the radio was initialized
  • false if a clock failed to start

void nrf_to_nrf::read ( void * buf,
uint8_t len )

Read the next available payload

Call available() first. Each call removes one payload, however many bytes are read. This is different from RF24, where a payload stays in the RX FIFO until all of it has been read.

if (radio.available()) {
uint8_t length = radio.getDynamicPayloadSize(); // or getPayloadSize() for static payloads
radio.read(&data, length);
}
Parameters

lenNumber of bytes to copy into buf. Use getDynamicPayloadSize() to get the payload's length. Bytes past the end of the payload are not meaningful.
Note

bool nrf_to_nrf::write ( void * buf,
uint8_t len,
bool multicast = false,

Transmit a payload to the address set with openWritingPipe()

Call stopListening() first. This blocks until an ACK is received or all retries have been used (see setRetries()). If the ACK carries an ACK payload, read it with available() and read() afterwards.

radio.stopListening();
radio.write(&data, sizeof(data));
Parameters
bufPointer to the data to be sent
lenNumber of bytes to be sent. With static payloads, a full getPayloadSize() packet is always sent, and the bytes after len are not zeroed. With dynamic payloads, len can be up to the size passed to enableDynamicPayloads(). With encryption, 12 more bytes (IV, counter and MIC) are added, and they must fit too.
multicasttrue sends the payload once without waiting for an ACK. enableDynamicAck() is not needed. The receiver still sends an ACK if auto-ack is enabled on its pipe.
doEncryptionfalse sends this payload unencrypted when encryption is enabled
Returns
  • true if an ACK was received. Also true, even if the payload was not received, if multicast is true or auto-ack is disabled on pipe 0.
  • false if no ACK was received after all retries

◆ startListening()

void nrf_to_nrf::startListening ( bool resetAddresses = true)

Start listening on the pipes opened for reading

  1. Call openReadingPipe() first.
  2. Call stopListening() before calling write().
  3. Call available() to check for incoming payloads, and read() to get them.

Open reading pipe 1 using address 0xCCCECCCECC

uint8_t address[] = {0xCC, 0xCE, 0xCC, 0xCE, 0xCC};
radio.openReadingPipe(1, address);
radio.startListening();
Note
openWritingPipe() uses pipe 0's address for transmitting, so this restores the address last set for reading pipe 0 by openReadingPipe().

resetAddressesUsed internally; leave as the default

◆ enableRxInterrupt()

bool nrf_to_nrf::enableRxInterrupt ( uint8_t depth = 3)

Receive packets from the radio interrupt, so a slow loop() doesn't leave the radio idle. available() and read() are used as normal. Don't use BLE in the same sketch.

Note
The library defines the radio interrupt handler, so a sketch can't define its own.

This is called automatically on begin(), so if you want to disable it, call disableRxInterrupt() after the radio and/or network/mesh has been configured.

Parameters
depthThe number of packets to queue, from 1 to 254. Uses (depth + 1) * (payload size + 2) bytes of RAM, plus depth * (payload size + 2) for the ACK payload queue if enableAckPayload() is called.
Returns
false if depth is invalid, there isn't enough memory, or this was already called

void nrf_to_nrf::openReadingPipe ( uint8_t child,
const uint8_t * address )

Open a pipe for reading

Up to 8 pipes (0-7) can be open for reading at once. Open all the required reading pipes, then call startListening().

Note
Pipe 0 stores a full address. Pipes 1-7 share every byte except the first, and each call for one of them sets the shared bytes for all of them. Pass the full address for each pipe, with only the first byte different:
uint8_t addresses[][6] = {"Prime", "2Node", "3Node", "4Node"};
radio.openReadingPipe(0, addresses[0]); // address used is "Prime"
radio.openReadingPipe(1, addresses[1]); // address used is "2Node"
radio.openReadingPipe(2, addresses[2]); // address used is "3Node"
radio.openReadingPipe(3, addresses[3]); // address used is "4Node"
Warning
openWritingPipe() uses pipe 0's address for transmitting. If pipe 0 is opened for reading, its address is restored by every startListening().

◆ writeAckPayload()

bool nrf_to_nrf::writeAckPayload ( uint8_t pipe,
void * buf,
uint8_t len )

Load a payload to send back in the ACK for the next packet received on pipe

With the RX interrupt enabled (the default), payloads are queued like the NRF24 TX FIFO. Up to the enableRxInterrupt() depth can be queued, so one can be loaded for each packet the RX queue holds. Each packet received takes the oldest payload queued for its pipe and sends it once; a retransmitted packet gets the same payload again. If none is queued for that pipe, a plain ACK is sent. Payloads can be at most getPayloadSize() bytes, including encryption overhead. Call enableAckPayload() first; it allocates the queue.

In polling mode (disableRxInterrupt()), one payload is stored. It is sent with the ACK for the next packet on pipe, re-sent if that packet is retransmitted, and discarded when the next new packet arrives.

This can be called before and after startListening().

Note
Use dynamic payloads (enableDynamicPayloads()) on both nodes. Unlike RF24, enableAckPayload() doesn't enable them.
See also
  • enableAckPayload()
  • flush_tx()
Parameters
pipeWhich pipe (0-7) will get this response
bufPointer to the data to send
lenLength of the data to send
Returns
false if the queue is full, the payload is too large, or with the RX interrupt, if ACK payloads aren't enabled or there wasn't enough memory for the queue

examples/RF24/AcknowledgementPayloads/AcknowledgementPayloads.ino.

◆ enableAckPayload()

void nrf_to_nrf::enableAckPayload ( )

Enable custom payloads in the acknowledgement packets

ACK payloads are a handy way to return data to senders without changing the radio modes on both nodes. Call this on both the transmitting and receiving nodes.

With the RX interrupt, this also allocates the ACK payload queue used by writeAckPayload(): depth * (payload size + 2) bytes of RAM, where depth is the enableRxInterrupt() depth.

◆ interframeSpacing

uint16_t nrf_to_nrf::interframeSpacing

The IEEE 802.15.4 standard defines a specific time that is alotted for the MAC sublayer to process received data. Usage of this interframe spacing (IFS) comes into play to avoid that two frames are transmitted too close to each other in time.

This is the time period in uS the radio will wait between the last bit of the previous transmission, and the first bit of the next transmission.

This is configured for compatibility with nRF24L01 radios. Can be set lower if communicating between nRF52x devices.

◆ enableEncryption

bool nrf_to_nrf::enableEncryption

Enable use of the on-board AES CCM mode encryption

Cipher block chaining - message authentication code (CCM) mode is an authenticated encryption algorithm designed to provide both authentication and confidentiality during data transfer. CCM combines counter mode encryption and CBC-MAC authentication

Users need to take extra steps to prevent specific attacks, such as replay attacks, which can be prevented by transmitting a timestamp or counter value, and only accepting packets with a current timestamp/counter value, rejecting old data.

Encryption uses a 5-byte IV and 3-byte counter, the sizes of which can be configured in nrf_to_nrf.h Maximum: 8-byte IV, 4-byte counter, plus the MAC/MIC is 4-bytes
